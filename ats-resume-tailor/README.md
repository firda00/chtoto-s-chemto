# ATS Resume Tailor

Сервис оценки соответствия резюме требованиям вакансии (**ATS Score**) и адаптации текста резюме
под зарубежные и локальные платформы найма (LinkedIn, Indeed, hh.ru).

Что умеет:

- читает резюме из `.pdf` (pypdf), `.docx` (python-docx), `.md` и `.txt` и делит его на разделы
  (контакты, о себе, навыки, опыт, образование) по заголовкам на русском и английском;
- разбирает вакансию в структуру `Vacancy`: название, must-have и nice-to-have навыки,
  взаимозаменяемые навыки («LangChain или LlamaIndex»), минимальный опыт в годах, ключевые слова.
  Работает на правилах, а если настроена LLM, дополнительно извлекает структуру по JSON Schema;
- считает ATS Score от 0 до 100 с разбивкой по компонентам, списком недостающих ключевых слов
  и конкретными рекомендациями;
- адаптирует резюме под вакансию и платформу через LLM, при этом действует guard
  «не выдумывать опыт»: раздел откатывается к оригиналу, если в нём появились новые компании,
  числа или навыки. Каждое изменение попадает в changelog;
- генерирует сопроводительное письмо (тоже только по фактам из резюме);
- экспортирует результат в `.md` и `.docx` (одна колонка, без таблиц, ATS-friendly);
- предоставляет CLI (`ats`) и HTTP API (FastAPI).

## Архитектура

```
 резюме (.pdf/.docx/.md/.txt)        вакансия (.txt/.md)
            │                                 │
     parsers.py                        vacancy.py ── (опц.) llm.py: JSON Schema extraction
  текст + разделы + контакты         must / nice / alternatives / min_years / keywords
            │                                 │
            └──────────────┬──────────────────┘
                           ▼
                      scoring.py  ←── skills.py (словарь навыков + синонимы)
                ATSScore: total, components, missing, suggestions
                           │
                           ▼
                      tailor.py ──► llm.py (OpenAI-совместимый API | MockLLM)
           TailoredResume + changelog  │  guard: новые компании, числа, навыки → откат раздела
                           │
                           ▼
                       export.py ──► resume_<platform>.md / .docx / _changelog.md
                           │
                cli.py (typer)   api.py (FastAPI)
```

## Как считается ATS Score

`total = Σ weightᵢ · scoreᵢ`, где `scoreᵢ ∈ [0, 1]`, а сумма весов равна 100.

| Компонент | Вес | Как считается |
|---|---|---|
| `keywords` | 40 | `0.75 · (найдено must / всего must) + 0.25 · (найдено nice / всего nice)`. Учитываются синонимы (`Python` ← `python3`, `LLM` ← `large language model`, `большие языковые модели`, `Kubernetes` ← `k8s`, `Vector DB` ← `pgvector`, `qdrant`, …). Группа взаимозаменяемых навыков («PyTorch или TensorFlow») засчитывается, если найден хотя бы один навык из неё. Если в вакансии нет nice-to-have, весь вес отдаётся must-have |
| `similarity` | 20 | Косинусная близость TF-IDF резюме и вакансии по символьным 3–5-граммам (`char_wb`, устойчиво к русской морфологии), синонимы предварительно нормализуются. Итог: `min(1, cos / 0.4)` |
| `sections` | 15 | Полнота разделов: опыт 0.30, навыки 0.25, контакты 0.20, образование 0.15, о себе 0.10 |
| `experience` | 15 | Сумма периодов работы (пересечения склеиваются, «по настоящее время» = сегодня): `min(1, лет_в_резюме / лет_в_вакансии)`. Если требования нет, 1.0. Если даты не распознаны, 0.5 |
| `formatting` | 10 | `1.0 −` штрафы: таблицы −0.30, изображения −0.15, > 1100 слов −0.20, < 150 слов −0.20, > 2 стр. PDF −0.10, нет email −0.20, нет телефона −0.10, нет заголовков −0.15, текст не извлекается −1.0 |

Рекомендации (`suggestions`) строятся из найденных проблем. Это недостающие must-have с подсказкой,
куда их добавить (только если навык действительно есть), желательные навыки, нехватка лет опыта,
отсутствующие разделы, исправления red flags, а также слова вакансии с наибольшим весом,
которых нет в резюме.

## Быстрый старт

```bash
cd ats-resume-tailor
uv sync

# ATS Score
uv run ats score --resume data/sample_resume.md --vacancy data/sample_vacancy.txt
uv run ats score --resume data/sample_resume_en.txt --vacancy data/vacancies/ai_engineer_en.txt --json

# как распознана вакансия
uv run ats vacancy --vacancy data/vacancies/ml_engineer_ru.txt

# адаптация под платформу: out/sample_resume_linkedin.{md,docx} + _changelog.md
uv run ats tailor --resume data/sample_resume.md --vacancy data/sample_vacancy.txt --platform linkedin --out out/

# сопроводительное письмо
uv run ats cover-letter --resume data/sample_resume.md --vacancy data/sample_vacancy.txt --platform hh --out out/

# тесты и линт
uv run pytest -q
uv run ruff check .
```

Флаг `--mock` принудительно включает `MockLLM`, флаг `--llm` включает реальную LLM.
Без флагов режим выбирается автоматически: если задан `LLM_API_KEY` или `LLM_BASE_URL` указывает
на localhost, используется реальная LLM, иначе мок.

Платформы (`--platform`):

- `linkedin`: About от первого лица, сначала идёт опыт, навыки отдельным списком;
- `indeed`: простой текст и стандартные заголовки на английском;
- `hh`: «Ключевые навыки» в виде тегов и раздел «О себе» из 3–5 предложений;
- `generic`: ATS-friendly в одну колонку.

`data/sample_resume.docx` собирается из `.md` скриптом `uv run python scripts/make_sample_docx.py`.

## Переменные окружения

См. `.env.example`.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `LLM_BASE_URL` | `https://openrouter.ai/api/v1` | OpenAI-совместимый endpoint (для Ollama: `http://localhost:11434/v1`) |
| `LLM_API_KEY` | — | ключ провайдера. Без ключа и с нелокальным endpoint включается `MockLLM` |
| `LLM_MODEL` | `qwen/qwen3-8b` | модель |
| `LLM_MOCK` | `0` | `1` принудительно включает мок (так работают тесты) |

## API

```bash
uv run uvicorn ats_tailor.api:app --reload
```

| Метод | Путь | Вход | Выход |
|---|---|---|---|
| GET | `/health` | — | `{"status": "ok", "llm": "mock"}` |
| POST | `/score` | JSON `{resume_text, vacancy_text}` **или** multipart: `resume_file` (pdf/docx/md/txt), `vacancy_text` или `vacancy_file` | `{vacancy, score}` |
| POST | `/tailor` | то же + `platform` | `{vacancy, tailored}` (sections, changelog, warnings, score_before/after) |
| POST | `/cover-letter` | то же + `platform` | `{text, used_keywords, warnings}` |

```bash
curl -X POST localhost:8000/score \
  -F "resume_file=@data/sample_resume.docx" \
  -F "vacancy_text=<data/sample_vacancy.txt"

curl -X POST localhost:8000/tailor -H "Content-Type: application/json" \
  -d '{"resume_text": "...", "vacancy_text": "...", "platform": "hh"}'
```

Ошибки: `422` возвращается при невалидном вводе или неизвестной платформе, `415` при неподдерживаемом
формате файла, `413` при файле больше 5 МБ.

## Guard «не выдумывать опыт»

После ответа LLM каждый изменённый раздел сравнивается с исходным резюме. Раздел откатывается,
а в changelog появляется запись `reverted`, если в нём появились:

- навыки из словаря, которых нет в исходном резюме;
- числа, даты или проценты, которых нет в резюме (разрешено только то, что есть в названии вакансии);
- организации: `ООО/АО/LLC/Inc …`, названия в «ёлочках», «at/в компании X», а в русском тексте ещё
  и латинские имена собственные, которых нет в резюме и в словаре навыков.

В сопроводительном письме строки с неподтверждёнными навыками или числами удаляются, и об этом
выдаётся предупреждение.

## Ограничения

- Словарь навыков (`skills.py`) составлен вручную под IT/ML-вакансии. Навыки вне словаря
  распознаются как «технические токены» (CamelCase, аббревиатуры, `C++`), но синонимов у них нет.
- Русская морфология учтена частично: синонимы перечислены в нескольких формах, а similarity
  считается по символьным n-граммам. Лемматизации нет.
- Разделы определяются по заголовкам. Двухколоночный PDF pypdf может склеить в неверном порядке,
  и формат это не исправит (поэтому за таблицы и колонки ставится штраф).
- Даты опыта распознаются в форматах `03.2021 — 06.2023`, `Jan 2020 - Present`,
  `март 2021 — по настоящее время`, `2019 — 2021`. Свободный текст («полтора года») не распознаётся.
- Guard эвристический: он ловит новые компании, числа и навыки, но не перефразирование, меняющее
  смысл (например, «участвовал» → «руководил»). Changelog нужно просматривать.
- Рекомендации всегда выдаются на русском, даже для EN-резюме.
- Порог similarity (0.4) и веса подобраны на демо-данных, а не на реальной разметке рекрутеров.

## Что замокано

- **LLM.** `MockLLM` (`llm.py`) работает детерминированно и без сети. Для адаптации он переносит
  релевантные навыки в начало, добавляет в навыки ключевые слова, которые уже подтверждены текстом
  резюме, и дописывает в summary строку с совпадающими компетенциями. Письмо он собирает по шаблону
  из пунктов опыта. Извлечение вакансии в мок-режиме идёт только по правилам.
  С реальной LLM (`OpenAILLM`, OpenAI-совместимый API) код написан, но в тестах не вызывается.
- Все тесты офлайн: `LLM_MOCK=1` выставляется автоматически. DOCX и PDF генерируются прямо в тестах
  (PDF собирается через pypdf, латиницей).
- Демо-данные в `data/` синтетические: имена, контакты, компании и вузы вымышлены.
