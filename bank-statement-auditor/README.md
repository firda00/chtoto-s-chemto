# Smart Subscription & Bank Statement Auditor

Скрипт финансового аудита: парсит банковские выписки (CSV/PDF), категоризирует траты и
находит регулярные подписки — в том числе **забытые** (спортзал, в который вы больше не
ходите; пробный период, который тихо стал платным), повышения цен, двойные списания и
необычные всплески трат. Всё работает локально, без сети.

## Что умеет

- **Парсинг выписок**: CSV трёх разных «банковских» форматов + произвольные CSV с
  похожими колонками (автоопределение), PDF (таблицы через `pdfplumber`, запасной
  построчный regex для PDF без таблиц).
- **Нормализация**: суммы вида `125 000,00` / `125,000.00` / `(99.90)` / `150.00-`,
  валюты (`сум`, `so'm`, `860`, `$` → ISO), имена мерчантов (убираются маски карт, ID
  транзакций, даты, `ООО/LLC/MCHJ`, города и коды стран; кириллица транслитерируется:
  `ЯНДЕКС.ПЛЮС МОСКВА` → `YANDEX PLUS`).
- **Категоризация**: правила по ключевым словам на RU/EN/UZ (еда, транспорт, подписки,
  связь/коммуналка, здоровье/спорт, развлечения, покупки, переводы, наличные, зарплата)
  + опциональный LLM-фолбэк для неизвестных мерчантов со structured output (Pydantic).
- **Подписки**: период (неделя / 2 недели / месяц / квартал / год), уверенность,
  следующее списание, стоимость в месяц/год, флаги «забыта?», «цена выросла»,
  «пробный → платный», «дубль», «мелкая и долгая», «уже не активна».
- **Отчёты**: консоль (rich), `report.md`, `report.html` (самодостаточный, без JS),
  `report.json`: траты по категориям и месяцам, топ мерчантов, таблица подписок с
  подсказками «отменить?», аномалии.

                         └──► pdf_parser ─┤   (таблицы pdfplumber → regex по строкам)
                                          ▼
                              list[Transaction]  ← normalize (суммы, валюты, мерчанты)
                                          │
                                          ▼
                              categorize (правила RU/EN/UZ → LLM-фолбэк через llm.py)
                                          │
                     ┌────────────────────┼─────────────────────┐
                     ▼                    ▼                     ▼
             subscriptions         anomalies (дубли,      pandas-агрегаты

              forgotten)                 │                     │
                     └───────────────► AuditReport ◄───────────┘
                                          │

## Поддерживаемые форматы

| Файл в `data/` | Профиль | Кодировка / разделитель | Колонки | Даты, суммы |
|---|---|---|---|---|
| `statement_uzbank.csv` | `uz_debit_credit` | cp1251, `;`, «шапка» банка и строка «Итого» | `date;description;debit;credit;balance` | `05.04.2026`, `126 300,00` |
| `statement_rubank.csv` | `ru_signed_amount` | utf-8, `,` | `Дата,Операция,Сумма,Валюта` | `2026-04-05 14:32`, `-126300.00`, валюта `сум` |
| `statement_sample.csv` | `generic_en` | utf-8, `,`, новые операции сверху | `Posted Date,Description,Amount,Currency,Reference` | `04/05/2026` (MM/DD), `"-126,300.00"` |
| `statement_small.pdf` | PDF-таблица | — | `Date, Description, Amount, Currency` | `05.04.2026`, `-126 300.00` |

Все три CSV содержат **одни и те же 318 операций** и парсятся в идентичные списки
`Transaction` (это проверяется тестом). Помимо трёх профилей, колонки распознаются по
синонимам на RU/EN/UZ (`Sana/Tavsif/Chiqim/Kirim`, `Transaction Date/Details/Withdrawal/
Deposit` и т.п.); формат даты подбирается так, чтобы подошли **все** значения колонки
(`01/02` vs `02/25` однозначно разводит DD/MM и MM/DD; при полной неоднозначности —
день первым). `audit formats` выводит список профилей.

## Как работает детектор подписок

1. **Кандидаты**: только списания, без категорий «переводы», «наличные», «зарплата»;
   группировка по нормализованному мерчанту (поэтому `SPOTIFY ID 30458812` и
   `SPOTIFY ID 99112233` — один мерчант).
2. **Дубли**: внутри группы операции «тот же день + та же сумма» схлопываются, лишние
   запоминаются как `duplicate_charge`.
3. **Кластеры сумм**: суммы сортируются и режутся на кластеры с допуском ±12% (курсовые
   колебания при оплате в валюте).
4. **Склейка ценовых сегментов**: кластеры, идущие друг за другом во времени (каждый ≥ 2
   списаний), склеиваются, если общий ряд остаётся периодическим. Так `29 900 × 3` +
   `39 900 × 3` становятся одной подпиской с флагом `price_increase`.
5. **Период**: медиана интервалов сопоставляется с эталонами (7±2, 14±3, 30.44±5,
   91±12, 365±20 дней). Все интервалы должны укладываться в допуск (при ≥ 5 интервалах —
   80%); минимум повторов: неделя — 4, месяц — 3, квартал/год — 2 (для двух повторов
   нужна «чистая» группа и сумма с точностью до 0.5%).
6. **Уверенность** = 0.35·регулярность интервалов + 0.25·стабильность суммы (CV внутри
   сегментов) + 0.2·число повторов + 0.2·«чистота» (доля ряда среди всех операций
   мерчанта). Ряды с уверенностью < 0.5 отбрасываются.
7. **Флаги и «забытость»** (только для активных подписок):

   | Флаг | Условие | Вес |
   |---|---|---|
   | `usage_stopped` | у мерчанта/«семейства» (тот же первый токен) были другие траты (бар в зале, тренер), но последние ≥ 60 дней назад, а списания идут | 0.6 |
   | `no_related_activity` | категория «здоровье/спорт», и за весь период ни одной связанной операции | 0.5 |
   | `trial_to_paid` | перед первым платным списанием — «пробное» ≤ 25% от цены | 0.5 |
   | `small_recurring` | < 30 000 UZS (3 USD/EUR) в месяц и длится ≥ 120 дней | 0.3 |
   | `price_increase` | медиана двух последних сумм > медианы двух первых на 7%+ | 0.15 |
   | `duplicate_charge` | двойное списание в один день | — |
   | `inactive` | последнее списание старше периода + допуск (в нагрузку не входит) | — |

   `forgotten_score` = сумма весов; **≥ 0.5 → «ЗАБЫТА?»**. Для «связи и коммуналки»
   usage-флаги не ставятся (пользование интернетом в выписке не видно).
8. **Нагрузка**: `monthly_cost = amount · 30.44 / period`, `annual_cost = amount ·
   365.25 / period`; в итог («burn») входят только активные подписки; «экономия» —
   годовая стоимость забытых.

**Аномалии** (`anomalies.py`): дубли — тот же день, мерчант и сумма; всплески —
робастный z-score по медиане/MAD внутри категории (если в категории < 8 операций — по
всем тратам), порог z ≥ 6 и сумма ≥ 4× медианы.

## Быстрый старт

```bash
cd bank-statement-auditor
uv sync

# (необязательно) пересоздать синтетические выписки — детерминированно, seed=42
uv run python scripts/make_statements.py

uv run audit analyze data/statement_sample.csv --out out/     # консоль + out/report.{md,html,json}
uv run audit subscriptions data/statement_uzbank.csv          # только подписки
uv run audit categorize data/statement_small.pdf -n 20        # разметка операций
uv run audit categorize data/statement_rubank.csv --csv out/categorized.csv
uv run audit formats

uv run pytest -q
uv run ruff check .
```

Опции: `--currency USD` — валюта по умолчанию, если в файле нет колонки валюты;
`--llm` — LLM-фолбэк для мерчантов, которых не узнали правила; `-q` у `analyze` — без
вывода в консоль.

На Windows, если консоль показывает «кракозябры» при перенаправлении вывода, задайте
`PYTHONIOENCODING=utf-8`.

## Переменные окружения

Нужны **только** для `--llm` (см. `.env.example`):

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `LLM_BASE_URL` | `https://openrouter.ai/api/v1` | OpenAI-совместимый endpoint (Ollama: `http://localhost:11434/v1`) |
| `LLM_API_KEY` | — | ключ; без него `--llm` использует `MockLLM` |
| `LLM_MODEL` | `qwen/qwen3-8b` | модель |

LLM получает только нормализованное имя мерчанта, описание и сумму одной операции и
возвращает JSON по схеме `CategoryGuess` (`category`, `confidence`, `reason`); ответы
кешируются по мерчанту, невалидный ответ или ошибка сети → категория `other`.

## Приватность

- Всё выполняется локально: парсинг, категоризация правилами, детектор, отчёты.
- Сеть используется **только** при явном `--llm` с заданным `LLM_API_KEY`, и наружу уходят
  лишь описания неизвестных мерчантов (не вся выписка, не номера счетов). Для полностью
  офлайн-режима укажите локальную Ollama в `LLM_BASE_URL`.
- Маски карт и ID транзакций вырезаются из имён мерчантов; `report.json` не содержит
  сырых операций.
- `out/` в `.gitignore` — отчёты по реальным выпискам не попадут в репозиторий.

## Что замокано / ограничения

- **Данные синтетические**: `scripts/make_statements.py` (seed=42) генерирует 318 операций
  за апрель–сентябрь 2026 с заложенными паттернами (Netflix, Spotify + дубль, iCloud,
  Яндекс Плюс с повышением цены, Beeline, Uztelecom, забытый фитнес-клуб, MEGOGO с
  пробным списанием, отменённый IVI, всплеск — ноутбук в Texnomart). Форматы «похожи»
  на выгрузки узбекских/российских/международных банков, но не копируют конкретный банк.
- **LLM** в тестах — `MockLLM` (детерминированные ответы по подстроке); тесты не ходят в
  сеть и не требуют ключей. Реальный вызов `OpenAICompatLLM` в тестах не проверяется.
- PDF-выписка генерируется reportlab стандартным шрифтом, поэтому в ней только латинские
  описания; сканы (OCR) не поддерживаются.
- Мультивалютные выписки: суммы считаются в основной (самой частой) валюте, операции в
  других валютах только подсчитываются — конвертации курсов нет.
- Пороги детектора подобраны под помесячные потребительские подписки и настраиваются через
  `DetectorConfig`.
